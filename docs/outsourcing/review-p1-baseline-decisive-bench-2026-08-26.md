## 2. レビュー側が BENCH_RESULTS.md 全文から確認した構造的事実

- stage a (12.91) = `--cpu-moe` あり・**global-LRU 無し・q\* 無し**。
  つまり歴代最高値は「ミスした expert を PCIe コピーせず **CPU で直接計算する経路**」の数値である。
- A の天井試算 (~6 t/s) は全 miss を転送する場合の下限見積りであり、
  **glru コピー経路専用の bound**。CPU 直計算経路 (実績 12.91) はこれに拘束されない。
- A の対照 4.34-4.50 は launcher (`run-qstar-trace.ps1`) 由来のため slot32 + glru 付きの疑いが強い
  = スラッシング経路の数値であり、素ベースラインではない可能性が高い。
- ただし「graphs on 試行 4.50」は矛盾を残す (glru 有効時はコード自身が graphs を強制無効化するはず)。
  → **A 対照の実際のフラグは誰も確定させていない。だからこそ実験で決める。**
- 参考: line 74 B0 の「slot キャッシュがゲートで無効化され実質スロットレス」の前例あり。
  slot 系フラグは黙って無効化される罠があるため、起動ログの確認を必須にする。
